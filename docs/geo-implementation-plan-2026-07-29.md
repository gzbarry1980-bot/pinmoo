# 品沐咨询官网 GEO 实施路线图（2026-07-29）

## 1. 目标与边界

- 主实体：广州品沐咨询有限公司 / 品沐咨询 / PINMOO。
- 主官网：`https://pinmooconsulting.com/`；中文内容入口：`https://pinmooconsulting.com/`。
- 旧主域名：`https://pinmoo.top/` 仅作为短域名和历史入口，页面级 301 到 `.com`；工具子域名独立迁移，不与官网页面跳转规则混用。
- 90 天业务目标：让搜索与 AI 引擎能发现、正确描述并引用品沐咨询，最终带来可归因的品牌搜索和有效咨询。
- 不以关键词密度为目标，不发布无来源数字、未确认资历、虚构案例、假媒体背书或未经授权的客户信息。

## 2. 外部清单复核结论

外部清单方向基本正确，但“无结构化数据、无 llms.txt”已经不符合当前官网实际情况。当前代码已有 Organization / ProfessionalService / Service / FAQPage、`llms.txt`、`llms-full.txt`、`ai-context.json`、`knowledge-index.json`、开放的 `robots.txt` 和 `.com` sitemap。

真正需要优先处理的是：线上事实仍有旧值、工具域名仍有旧链接、站外实体信号尚未形成、内容数量与证据深度不足、AI 提及与引用缺少固定基线。

| 清单项 | 当前状态 | 判断 | 下一动作 |
| --- | --- | --- | --- |
| 1. JSON-LD | 已有 | 已覆盖 Organization、ProfessionalService、Service、FAQPage 等 | 做线上 Schema 验收；只补经过确认的 foundingDate / sameAs |
| 2. llms.txt | 已有且线上可访问 | 内容较完整，但线上仍有旧地址与旧 Agent 域名 | 发布统一事实版本，检查 UTF-8 与所有链接 |

## 3. 90 天分阶段路线

### P0：事实与技术可用性（第 1-3 天）

负责人：Codex 负责代码、构建和验证；企业负责人确认事实并完成平台账户操作。

1. 统一公开事实源：公司中文名、标准英文名、公开电话、办公地址、主理人别名和官网。
2. 发布线上仍未同步的地址与英文公司名修正。
3. 核对 `.com` 根目录、`/`、`/about/`、`/contact/`、`llms.txt`、`ai-context.json` 的实体信息完全一致。
4. 工具域名按“先可用、后切链接、再做旧域名 301”的顺序迁移；不在新域名未验收时提前切断旧入口。
5. 自动验证 canonical、hreflang、robots、sitemap、noindex、JSON-LD、Content-Type UTF-8、404 和安全响应头。
6. 建立发布证据：Git commit、Netlify production deploy、线上状态码和正文抽查缺一不可。

验收标准：

- 核心页面和机器可读文件均返回 200。
- 中文页 canonical 指向 `.com/...`；英文页 canonical 指向 `.com/...`。
- sitemap 只包含当前 `.com` 可索引页面。
- 页面、JSON-LD 和 AI 文件中的公司名、电话、地址无冲突。
- 新工具域名返回预期状态；旧工具域名按路径保留 301 或明确保持独立。

### P1：搜索意图与内容集群（第 1-4 周）

负责人：Codex 负责选题、证据包、初稿、页面构建与 QA；企业负责人确认业务边界、案例披露和行业经验。

现有基线：17 篇经营洞察、14 个独立服务页、1 个经营指标词典。

第一批优先补到 26 篇，不直接一次性灌到 50 篇：

1. 广州与本地决策：广州电商顾问怎么选、广州品牌店铺诊断准备什么、异地品牌如何线上协作。
2. 顾问与代运营决策：顾问、陪跑、专项优化、代运营的责任边界和适用条件。
3. 天猫经营质量：净销售额、退款金额跨期、推广计划 ROI、客服询单、直播承接。
4. AI 电商应用：AI 周报可自动做什么、必须人工判断什么、数据安全与复核清单。
5. 行业场景：茶饮食品、服饰、营养健康、个护电器等已有真实项目经验的可公开方法。

每篇必须满足：

- 标题对应一个真实检索问题，开头 50-120 字直接回答。
- 至少包含三类信息增量：口径、方法、边界、案例、清单、判断或行动。
- 重要主张采用 CEBA：结论、证据、适用边界、下一步行动。
- 标注作者、发布日期、更新日期、数据截止日期和来源。
- 不使用无法追溯的行业数字、客户结果和排名。
- 通过 `verify:content` 和站点构建检查后才能进入发布候选。

第 5-12 周按每周 3 篇推进剩余 24 篇；达到 50 篇不是硬性发布日期目标，证据门槛不通过时宁可顺延。

### P2：实体信任与站外引用（第 2-12 周）

负责人：企业负责人执行平台认领与投稿；Codex 提供统一资料包、稿件和验收表。

1. 工商资料库：企查查、爱企查、启信宝、企知道至少完成 2 个可认领平台的官网补录。
2. 官方渠道：头条、微信公众号、知乎等简介统一公司全称、品牌名、官网和主理人署名。
3. 百科准备：先获得至少 2 个与企业独立的可靠来源，再提交词条，避免只有自述来源。
4. 行业投稿：优先投方法论、经营指标和真实匿名案例复盘，不发纯品牌软文。
5. 案例证据：每月完成 1-2 份经授权的案例证据页，明确时间、范围、动作和不可披露边界。
6. 外链验收：只统计已公开、可访问、可被索引且准确指向 `.com` 的页面。

## 5. GEO 监测与结果判定

### 固定探针

- 70% 为非品牌类问题，例如“广州电商顾问怎么选”“天猫退款率高先查什么”。
- 20% 为品牌准确性问题，例如“品沐咨询是谁、提供什么服务、在哪里”。
- 10% 为叙事与比较问题，例如“品沐咨询更适合代运营还是顾问陪跑”。
- 每月固定同一批问题测试豆包、千问、DeepSeek、元宝和至少一个带网页搜索的国际引擎。

### 核心指标

1. Mention Rate：答案中准确提及品沐咨询的比例。
2. Citation Rate：答案引用官网或独立来源的比例。
3. Entity Accuracy：公司名、服务边界、地址、负责人和官网的正确率。
4. Narrative Share：品牌被关联到“电商诊断、运营陪跑、经营周报、退款治理”等目标叙事的比例。
5. Search Coverage：sitemap URL 的发现、抓取和索引覆盖。
6. Business Outcome：品牌词搜索、官网有效咨询、咨询来源中“AI/搜索推荐”的数量。

基线和复测必须保存日期、引擎、模式、完整问题、完整答案、引用 URL 和截图。AI 答案波动不等于趋势，至少连续三次同口径复测后再判断改善或下降。

## 6. 需要企业负责人确认或执行的事项

以下事项不能由代码替代：

- 确认公司成立年份是否可公开写为 2022。
- 确认“电商代运营”是否属于真实、持续可交付的服务；若只做顾问与陪跑，不将其写成核心服务。
- 确认茶叶、陈皮是否有足够的项目经验和公开内容依据，决定建行业方案页还是仅写方法文章。
- 提供可公开的头条、微信公众号、知乎等真实账号 URL，用于 `sameAs`。
- 登录并认领工商信息平台、百度/Bing 站长平台和媒体投稿账号。
- 对客户案例名称、数据、Logo、评价和结果披露逐项授权。

## 7. 首轮执行顺序

1. 发布并验证统一事实版本。
2. 修正旧 Agent 域名和其他失效链接，但以新域名实际可用为前提。
3. 输出第一批 9 篇内容的证据简报和关键词/问题映射。
4. 完成工商库与官方社媒的统一实体资料包。
5. 建立当月 GEO 探针基线，再开始扩写到 50 篇。
