# 电商经营报告工作流

本文档说明 Pinmoo AI 网站端从上传文件到导出 Word 的第一阶段 MVP 流程。

## 第一阶段目标

跑通“上传多文件 → 识别报表 → 解析 Excel/CSV → 生成周报预览 → 导出 Word”的闭环。

暂不要求 PDF、PPT、多平台深度适配、模板管理和云端历史库。

## 页面入口

网站功能入口为“电商经营报告”。用户进入后填写：

- 品牌名称
- 店铺名称
- 平台
- 报告类型：周报/月报
- 报告用途：品牌方正式版/内部诊断版/会议汇报版
- 统计周期开始日期和结束日期
- 经营报表文件

## 上传与识别

用户可一次上传多份文件。第一阶段重点支持：

- `.xlsx`
- `.xls`
- `.csv`

系统根据文件名和表头识别模块：

- “首页”“数据概览” → 首页经营数据
- “商品”“宝贝” → 商品销售数据
- “流量来源”“无线店铺流量来源” → 流量来源数据
- “客户概况”“会员” → 客户结构数据
- “客服绩效”“客服团队” → 客服数据
- “直播业绩” → 直播数据
- “光合”“内容” → 内容种草数据
- “计划报表”“推广”“关键词”“创意”“单元” → 推广计划数据
- “退款”“售后” → 退款数据

## 数据标准化

解析后的数据会进入统一经营模型，核心字段包括：

- 支付金额、净支付金额、净销售额、退款金额
- 访客数、支付买家数、支付转化率、客单价
- 老买家支付金额、主动回访支付金额
- 推广花费、推广成交金额、ROI、展现、点击、点击率、点击转化率、加购
- 直播观看、商品点击、播中成交、播后成交
- 客服咨询、响应、询单转化、客服成交、客服退款

## 报告生成

系统生成品牌方正式周报，默认包含：

1. 本周一句话结论
2. 本周经营总览：净销售额视角
3. 图表快照：支付/退款/净销售额、流量结构、每日销售、商品风险、推广 ROI
4. 每日销售与退款表现
5. 流量来源结构与转化质量
6. 商品销售表现与退款风险
7. 推广投放表现
8. 客户结构与客服承接
9. 直播与内容种草表现
10. 下周期执行计划
11. 微信群发送话术

## 交付等级

系统会按数据完整度和模块覆盖情况生成 A/B/C 交付等级：

- A级：品牌方正式版，可直接交付。核心经营、商品、流量和风险数据较完整。
- B级：内部诊断版，建议补数后再正式发送。已能形成经营判断，但部分明细不足。
- C级：数据不足，仅适合作为草稿参考。需补齐首页经营、商品明细、流量来源和退款明细。

交付等级会同步出现在网页预览、TXT 正文和 Word 导出中。

## 补数指引

当用户上传的报表不完整时，右侧栏会优先显示“需要优先补充的数据”，并说明：

- 需要补充的报表名称。
- 在平台后台大致从哪里下载。
- 补齐后能增强报告中的哪一段。
- 为什么该数据会影响正式交付判断。

这样不同客户上传不同报表时，系统不要求一次性固定模板，而是先生成可用草稿，再引导用户按缺口补数后重新生成。

## 口径说明

报告必须说明：

- 支付金额用于观察成交规模。
- 首页净支付金额用于观察平台首页口径下的净成交趋势。
- 店铺绩效净销售额通常用于判断真实经营质量。
- 推广计划报表可能与生意参谋推广归因口径存在差异。
- 商品退款率过高或退款金额高于当期成交金额时，可能涉及历史订单在本期退款。

## 导出

第一阶段支持导出 Word。默认命名：

`品牌名_平台_周经营复盘报告_品沐咨询正式版_开始日期-结束日期.doc`

后续阶段再扩展 PDF、PPT、模板库和云端历史报告库。
