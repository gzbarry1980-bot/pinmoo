### 操作 2：修复线上「官方数据加载失败：Cannot set properties of null (setting 'innerHTML')」

**任务描述**
线上各页报运行时错误并被 catch 包成「官方数据加载失败」。根因是独立页重构后每个 route 是独立页面，但 `app.js` 的 `init()` 仍在**每个页面无条件**执行只属于「求证工作区」的初始化，撞 null 抛错。

**关键操作步骤**
1. 定位报错：grep `官方数据加载失败` 命中 `app.js` catch 块；真正的 `setting 'innerHTML'` 来自 `setupSelectors()` line 99 对 `#admissionDistrict` 等无判空赋值。
2. 确认 4 个函数在 init 阶段被全页无条件调用又无判空：`setupSelectors()`、`syncQuotaInterface()`、`renderTargetYears()`、`refreshTargetSchoolList()`（它们操作的元素只存在于 verify 工作区，首页/方向/目标页没有）。
3. 给这 4 个函数加「元素不存在就跳过」守卫（行为不变，仅判空）：
   - `setupSelectors`：每个下拉框改为「存在才 set innerHTML+value」；`renderTargetYears`/`refreshTargetSchoolList` 仅在对应元素存在时调用。
   - `renderTargetYears`：开头 `if (!targetYearEl) return;`；`#policyBanner`/`#mode` 也判空。
   - `refreshTargetSchoolList`：开头 `if (!document.getElementById('targetSchoolName')) return;`；列表/结果元素判空。
   - `syncQuotaInterface`：开头 `if (!document.getElementById('quotaEligible')) return;`；内部 `#quotaDetails`/`#schoolBatch`/`#sourceSchoolId` 判空。
4. 发现遗留坑：special/unlock 页 JS 缓存号还停在 `g`（与首页 `h` 不一致），会导致这两页加载旧缓存 app.js、修复漏不到。用脚本统一把全站 `h`/`g` → `i`（含 app.js 内 engine.js/realistic-sim.js 的 import 缓存号）。
5. `node --check` 语法校验通过 → tar 管道 re-deploy 覆盖 `pages1`。

**结果说明**
- re-deploy 后 6 路由全 200；线上 app.js 含全部守卫；首页 HTML 引用 `app.js?v=20260725i`；engine.js 哈希仍为 `fc8f643c…`。
- 用户需硬刷新拉取 `?v=i` 新 app.js。
- 教训：`init()` 是全页共享入口，任何只属某 workspace 的初始化都要对元素存在性判空，否则独立页架构下必崩。
