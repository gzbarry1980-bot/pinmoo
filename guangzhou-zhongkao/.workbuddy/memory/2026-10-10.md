## 真实支付联调「代码侧前置」完成（同日，20:20）

交付物：`docs/真实支付联调与真机验收-2026-10-10.md`（操作手册）。

**已上线改动**
- **nginx 回调 exempt 限流**（重要）：新增 `location = /api/pay/notify` 与 `= /api/pay/refund-notify`（精确匹配，优先级最高，不挂 `limit_req`/`limit_conn`）。原因：微信 15s 内收不到 200 会阶梯重试，回调被 429 会拖慢开通。实测：回调 20 次全 200（429 × 0）；下单接口仍 401×10 → 429×14，**限流没被削弱**。nginx 备份 `.bak-prelive`。
- 事件日志新增 `notify_received`；`order_paid` 带 `via=notify|query`，用于区分「回调开通」还是「查单补单」——真实支付验收的硬证据。
- 密钥注入通道：`EnvironmentFile=-/etc/zhongkao-pay/env`（600）；PEM 走**文件路径**（systemd EnvironmentFile 不支持多行值），config.js 检测不到 `-----BEGIN` 时按路径读。模板 `server/deploy/zhongkao-pay.env.template`，安装脚本 `server/deploy/install-wxpay-env.sh`（自动 install PEM 到固定路径、更新 unit、重启、跑自检）。
- `server/scripts/check-wxpay-config.cjs`：L1 格式 / L2 自洽（私钥签名自验、**平台公钥指纹 ≠ 商户证书指纹**）/ L3 在线探针（`/v3/certificates` 验 Authorization、查不存在单号期望 404、回调 URL 公网可达、可选 `--probe-order` 诊断 appid↔mchid 绑定）。
- `server/test/wxpay-live.cjs`：真实联调，必须 `LIVE=1` 才执行（否则 SKIP 退出 0，不污染 CI）；支持 `--mode=order|watch|close|full`，校验微信侧 SUCCESS + 金额/appid/mchid/付款人一致 + 本地 PAID + 权益开通 + notify 到达 + `via=notify`。
