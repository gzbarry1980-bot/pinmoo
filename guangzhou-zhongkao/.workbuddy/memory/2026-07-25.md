## 修复：线上报「官方数据加载失败：Cannot set properties of null (setting 'innerHTML')」
- 根因：独立页重构后，每页独立成 route，但 `app.js` 的 `init()` 仍在**每个页面无条件**执行 `setupSelectors()` / `syncQuotaInterface()` / `renderTargetYears()` / `refreshTargetSchoolList()`。这些函数直接操作只属于某 workspace 的 DOM 元素（如 `#admissionDistrict` `#quotaEligible`），首页/方向/目标页上这些元素不存在 → 撞 null 抛错，被 init 的 catch 包成「官方数据加载失败」提示。报错信息里的 `setting 'innerHTML'` 正是 `setupSelectors` line 99 无判空赋值。
- 修复（行为不变，仅加守卫）：
  - `setupSelectors`：每个下拉框改为「元素存在才 set innerHTML+value」；`renderTargetYears`/`refreshTargetSchoolList` 仅在 `#targetYear`/`#targetSchoolName` 存在时调用。
  - `renderTargetYears`：开头 `if (!targetYearEl) return;`，`#policyBanner`/`#mode` 也判空。
  - `refreshTargetSchoolList`：开头 `if (!document.getElementById('targetSchoolName')) return;`，列表/结果元素判空。
  - `syncQuotaInterface`：开头 `if (!document.getElementById('quotaEligible')) return;`，内部 `#quotaDetails`/`#schoolBatch`/`#sourceSchoolId` 判空。
- 缓存版本号：special/unlock 页 JS 还停在 `g`（遗留不一致），统一把全站 `h`/`g` → `i`（含 app.js 内 engine.js/realistic-sim.js 的 import 缓存号），避免浏览器用旧缓存。
- 验证：re-deploy 到 pages1（覆盖），6 路由全 200；线上 app.js 含全部守卫；首页 HTML 引用 `app.js?v=20260725i`；engine.js 哈希仍为 fc8f643c…（禁区零改动）。
- 教训：`init()` 是「全页共享」入口，任何只属于某 workspace 的初始化都要对元素存在性判空，否则独立页架构下必崩。

## 修复：首页三大模块（三卡片）消失，只剩「扩展查询工具 / 功能概览预览」
- 现象：用户访问首页，三大模块入口区（方向版/目标校版/求证版）不显示，只看到次要入口（特长生/自主招生）与功能概览预览。
- 根因：`init()` 中 `const initialWorkspace = pendingDraft ? 'verify' : 'home'; setWorkspaceMode(initialWorkspace);`。`pendingDraft` 由 `prepareDraftRestore()` 从 localStorage 读草稿赋值——用户此前在求证版填过表留了草稿 → `pendingDraft` 为真 → 首页走 `setWorkspaceMode('verify')` → `landing.hidden = mode!=='home'`（app.js:168）把整个 `#landing`（三模块区）设为 hidden。CSS / access-gate 均无关（仅 @media print 隐藏 #landing，is-locked 只控制 .preview-note）。
- 修复：把分支改为——`isVerify`（存在 #verifyWorkspace）时才按 `pendingDraft` 决定 verify/home；**首页及其他独立页一律 `setWorkspaceMode('home')`**，不受 localStorage 草稿影响。求证版行为不变。
- 缓存版本号：`i` → `j`（全站 app.js/HTML）。
- 验证：re-deploy pages1 覆盖；6 路由 200；服务端 app.js 含「首页及其他独立页」分支；首页引 `app.js?v=20260725j`；engine.js 哈希不变。
