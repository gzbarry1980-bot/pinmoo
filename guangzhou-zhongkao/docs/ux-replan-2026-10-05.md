# 广州中考志愿模拟助手：页面与功能重规划

日期：2026年10月5日

状态：待评审方案。此次仅检查现有源码与数据并编写规划，未修改业务页面、算法或线上服务。

## 1. 改版目标

让家长从自己的问题直接进入：查一所学校、按分数找方向、检查已有方案。以“学校库＋统一志愿工作区”为中心，贯通查学校、收藏比较、生成或编辑方案、评估、调整。

第三、第四批是普通志愿模拟主线。第一批特长生、自主招生主要提供学校项目与信息查询；第二批是名额分配，按资格与来源初中提供专门入口。自主招生不标为第二批。

## 2. 现状依据与主要问题

以下结论来自本次读取的本地代码与数据，不代表已核验当前公网部署。浏览器连接因运行组件缺失失败，本轮未完成当前页面截图及真实点击审查。

| 现状 | 直接影响 | 改版处理 |
| --- | --- | --- |
| 首页主入口是方向版、目标校版、求证版，无独立学校库 | 查学校之前要先理解产品模式 | 首页首屏搜索，增加“查学校”一级导航 |
| `app.js` 中 `openSchoolDetail` 同时要求学校与志愿槽位；事件入口在预计去向列表 | 学校详情依赖已经做过方案 | 学校详情独立地址，个人机会和方案位置作为可选内容 |
| 学校筛选以当年、批次、考生条件的录取记录作为候选来源 | 缺记录或不符当前条件的学校容易看起来“查不到” | 学校基础索引负责查找；报考资格作为独立状态展示 |
| 搜索主要使用校名字符串包含匹配；列表截取前120条 | 常用简称不友好；部分学校被截断，没有明确翻页机制 | 别名与校区索引、联想结果、分页或加载更多 |

| 返回逻辑先恢复页面滚动位置，再判断浏览历史 | “上一处”不一定符合家长理解的“上一页” | 页面返回、流程上一步、返回方案分开定义 |

| 基础学校、统招历史、特长、自主招生及公开活动分开加载展示 | 同一学校资料割裂 | 统一学校档案，按来源与年份展示 |

数据盘点：

- 学校基础表311条记录，包括学校/校区及历史记录；不能直接等同311所现招普通高中。
- 257条记录有校区地址；住宿、年学费字段当前均无已核验值。
- 自主招生名单56所；公开活动目前7条，覆盖7所。
- 常规历史数据包标记为2021—2026，但2021年第三、第四批及2022年第三批结构化记录存在缺口。
- 所以学校页必须展示具体可用年度和缺失项；住宿、费用、出口表现不应凭空补全或作为已可靠筛选条件。

## 3. 一级导航

网页与小程序使用相同信息结构。桌面放顶栏，手机以底部导航承载主入口，保留足够底部空间。

| 入口 | 首要任务 | 页面主要内容 |
| --- | --- | --- |
| 首页 | 快速开始、继续上次操作 | 全局学校搜索、三个任务入口、最近学校、继续编辑当前方案 |
| 查学校 | 找学校、看资料、比较 | 学校库、独立详情、收藏、2—4校比较 |
| 志愿方案 | 生成、编辑、评估 | 按分数生成、按目标校生成、已有方案检查、第三/第四批志愿表、结果与调整 |
| 招生信息 | 查询特殊渠道及官方信息 | 特长项目、自主招生、开放日/校庆日、名额分配说明、批次与梯度规则 |
| 我的 | 找回自己的资料和方案 | 本机考生条件、收藏、多份方案、导入导出、解锁状态、设备权益、客服入口 |

首页减少重复介绍，首屏优先给“搜索学校”和“开始/继续方案”。产品说明与数据来源保留在次级位置。

## 4. 学校库：最高优先级

### 4.1 搜索规则

- 在首页和“查学校”都能输入校名；不要求先填写分数、区域或志愿。
- 支持全称、常用简称和已核实的历史名称。例如“培正”“华附”“铁一”；别名与曾用名映射需核验。
- 同校多校区先归在学校下，再明确展示校区、区域；不同校区录取记录保持独立。
- 联想结果直接进入学校详情，不要求再次选择模式或提交分析。
- 有历史记录而当前年度暂无招生记录的学校仍可查询，标注年份与状态。
- 搜索结果中不因家长分数或当前资格不匹配就隐藏学校。显示“资格待核对/当前条件不符/当前口径暂无数据”，并解释原因。
- 无结果时提供常用名提示、清除筛选与查看全部学校；不能只给空白列表。

### 4.2 列表与筛选

每张卡片优先显示：校名/校区、校址区、公民办、最新可用录取年度及口径、已核实的特长或自招标记。

主按钮“查看学校”，次操作“收藏”“对比”。加入志愿需再选择批次、位置，避免误加。

先提供数据可靠的筛选：区域、公民办、招生批次、特长项目、自主招生。住宿和学费待补齐来源后开放，并保留“资料未知”选项。

排序可选：关键词相关、户籍同区优先、同口径录取门槛、历史波动。门槛排序注明统计口径，不改名为学校质量排名。

### 4.3 独立学校详情

建议地址 `/schools/detail/?id=<稳定学校校区ID>`，可直接打开、刷新、分享。访问不依赖现有志愿方案。

| 区块 | 家长的问题 | 展示内容 |
| --- | --- | --- |
| 学校概况 | 这是哪所学校，在哪里？ | 简介、校区、公民办、类型、地址、招生范围；收费住宿及联系方式有来源才展示 |
| 历年录取 | 以前大概多少分，排第几志愿？ | 年度、批次、考生口径切换；最低分、末位志愿、末位考生分/同分序号；计划与实际人数分列 |
| 对我是否合适 | 我的条件能报吗？ | 可选填入统一考生条件；显示资格核对、估分机会区间、置信度、缺失条件 |
| 特长与自主招生 | 有没有对应项目？ | 项目、计划、文化控制要求、专业测试说明、自招历史100分制合成成绩、简章 |
| 开放日与咨询 | 何时去了解学校？ | 绝对日期、已结束/即将举行/未公布、来源、更新时间、已核实官方咨询方式 |

页面固定动作：收藏、加入对比、作为目标校、加入志愿。没有方案时进入新建流程；已有方案时只带入所选校区，先选位置。

各年度、批次、户籍/随迁/外区等口径不能混成单一“学校分数”。民办统一本口径成绩按官方字段展示，不强拆成户籍生与非户籍生。名额分配历史必须结合来源初中。

2026开放日放在历史活动中，不根据往年日期自动生成2027时间。出口表现后续单列参考卡，标明年份、分母与来源，不直接推断学校加工能力。

### 4.4 对比与收藏

可选2—4所学校/校区，按同年度、同批次、同考生口径比较门槛、末位志愿、区域、特长与已核实住宿/费用。缺失数据明确留空；不生成学校综合质量总分。

收藏只表示关注，不自动占用志愿位。比较后可带入目标学校分析或加入当前方案。

## 5. 志愿工作区：保留三种能力，统一过程

原有“方向版、目标校版、求证版”能力全部保留，呈现为一个工作区中的三种开始方式：

1. 按分数生成：输入估分区间及必要身份条件，生成初稿。
2. 围绕目标学校：选择或从学校档案带入目标校，查看分值目标与配套志愿。
3. 检查已有方案：空白表录入或导入，直接求证。

三种入口最终进入同一份方案、同一套评估结果。全局显示当前方案名称、目标年度与考生条件摘要；切换入口不静默覆盖已有方案。

推荐流程：确认考生条件 → 生成或编辑志愿 → 查看评估 → 选择调整 → 保存/导出。

### 5.1 考生条件

不填条件也可以浏览学校。需要判断报考资格与机会时再分步补充所需条件。填过的信息全流程复用；未知资格允许保留“待核对”，不能用默认值冒充已确认。

中心分、分数区间、户籍与升学区域等信息集中管理。住宿、收费、参考等级、来源初中等按相关场景展开。修改会影响资格的条件时，列出受影响志愿，标注待调整，不无提示清空。

### 5.2 志愿编辑

- 主视图为第三批6个、第四批6个志愿；第二批资格确认后才打开专门区域。
- 第一批及第二批已录取状态影响后续模拟，条件提示保留；信息查询仍可使用。
- 每一行都可以查看学校、替换、上下移动、删除；拖动以外提供手机和键盘可用的移动按钮。
- 替换采用搜索选择器：先看学校及口径，再选替换位置，避免长下拉框。
- 同一志愿条目重复应拦截；跨批次、不同招生计划的处理按当年规则判断，不仅按相同文字名称去重。
- 切换进取/均衡/稳健时展示具体变化：替换了哪些学校、冲稳保结构及风险如何变化；保留原方案可撤销。

### 5.3 评估结果

首屏给出方案合理度、主要风险、预计去向分布和最优先的1—3项调整。五项得分、逐志愿推演与历史依据按需展开。

明确分开：方案合理度评分、单校机会、整份方案下的最终去向概率。新页面继续调用现有计算核心；界面改版不人为把得分提高到80或100。

调整建议展示“第三批第几志愿：A改为B／移动到第几位”，同时提供调整前后结果。用户采用后重算，可撤销。不能为了高分自动改变学费上限、地区偏好或排除学校。

修改分数、资格或志愿后，旧结果立即标为“需要重新评估”，避免看到不对应当前方案的旧分数。

## 6. 返回、保存与跨页面连续性

- “首页”永远去真正首页，不执行历史回退。
- “返回学校列表”恢复关键词、筛选、页码和滚动位置。
- 从志愿表打开学校详情时，提供“返回当前方案”，恢复原志愿行。
- 从结果打开学校详情时，提供“返回评估结果”，保留当前结果及位置。
- 浏览器后退遵循页面历史；流程上一步只切换流程阶段，不再混用滚动历史。
- 新建方案默认空白；继续已有方案有明确卡片，不悄悄预填。
- 方案支持命名、另存、比较、恢复与删除；保存成功和失败都有反馈。
- 首期继续本机存储，说明换设备不会自动同步草稿；支持匿名导入导出。设备使用权与方案同步是两回事。
- 解锁完成后回到原来要查看的页面/方案，避免从首页重新走一遍。

## 7. 视觉与性能

延续深蓝主色和浅背景，压缩大段引导、重复标题及占屏横幅。继续三档字号，建议标题22px、正文16px、备注13px，通过字重与间距表达层级。学校列表和详情移动端优先。

每屏保持一个主要动作。底部导航与当前页操作区分层，预留安全距离，避免遮挡内容。交互目标建议至少44px；错误、加载、无数据与已过期状态不能只依赖颜色。

学校搜索先加载轻量索引，详细历史与专项资料按需加载；模拟运算提供进度，必要时移入后台计算。设置输入完成后再计算的时机，避免每输一个数字都阻塞页面。

## 8. 数据与权限安排

建议学校基本资料、历史公开数据及活动查询开放查看；个性化完整评估、方案补强和完整导出沿用序列号权益。具体边界在实现前作为产品配置确认，管理端仍独立保护。

优先补齐收藏较多或用户常查学校的官网/官微、招生咨询方式、住宿、收费、学校简况。每个字段保存来源、适用年度和核验时间；缺失有状态，有依据后再显示。

学校主键、校区、别名与历史名称集中维护。旧数据缺年、更名、校区变化不得静默拼接；统一学校资料服务供搜索、列表、详情、对比和志愿选择器使用。

## 9. 实施顺序与验收

| 阶段 | 交付范围 | 验收重点 |
| --- | --- | --- |
| A：先解决找学校 | 首页搜索、学校库、独立详情、全站校名入口、返回恢复 | 不填分数、不建方案，搜索“培正”即可打开档案；多校区清晰；返回保留搜索 |
| B：贯通选校与方案 | 收藏、对比、统一考生条件、多份方案、学校带入目标分析/志愿 | 同一所学校资料一致；收藏不等于填报；切换方式不覆盖方案 |
| C：重排编辑与结果 | 简化编辑、评分和去向摘要、建议前后对比、撤销、状态失效 | 固定输入与种子沿用原结果；每条建议能定位；修改后不展示旧结果 |
| D：资料与小程序适配 | 资料补齐、活动日期治理、统一导航、加载与错误恢复 | 网页与小程序能力对齐；按实际小程序能力验证导航和返回，不能只凭web-view推定一致 |

建议先完成A，再进入B/C；不把资料全量补齐作为学校库上线前置条件，但未知数据必须如实展示。

关键验收用例：

1. 首次用户从首页搜索培正，选择结果后直接到详情；不填写分数或地区。
2. 输入经核实的简称能检索；多校区不混淆；历史名称有标识。
3. 当前条件不满足某校报考要求时仍能看学校，并看到不能报的原因。
4. 查校返回列表，关键词、筛选与滚动位置保持。
5. 从第三批第3志愿看学校后返回，仍定位该行，顺序和其他选择不变。
6. 方向方案修改后打开另一模式，不覆盖已有方案；另存后可比较。
7. 每个历史分数同时显示年度、批次、校区及考生口径；无数据不显示0。
8. 住宿/费用未知不会被当作免费或不提供住宿；历史开放日不会显示为即将举行。
9. 解锁后回到原任务；收藏、方案、权益三种状态不混淆。
10. 390px手机布局可完成搜索、看校、填报、评估和返回；键盘可操作搜索与志愿排序。

## 10. 本轮建议决策

采用“学校库＋统一志愿工作区”的结构，先做查学校与学校详情。它最直接解决当前使用障碍，也为后续目标校分析、志愿选择和学校对比提供同一套基础。
