# 下一阶段：流程优化与资料采集计划

日期：2026-10-23（北京时间）。性质：规划稿，未执行下列开发、数据入库或新部署。

2026-10-25执行更新：首批流程优化与2021分数段补录已上线；详见[实际交付与遗留](flow-upgrade-20261025/README.md)。下列为原始规划，各项不能因首批发布而视为全部完成。

## 目标与判断依据

让家长完成“找到想读的学校 → 形成愿意接受的志愿 → 看懂风险并调整 → 保存后继续使用”。第三、第四批维持主流程；第一批提供专项资料查询，第二批按初中查看名额分配。

本计划使用产品规划方法，将页面问题、资料缺口、交付与验收对应起来。依据为当前源码、10月23日生产回执、学校数据及遗留清单；未把技术检查当作家长可用性测试。没有真实使用漏斗或付费转化基线，因此以下优先级按对报考正确性、任务完成和选校价值的影响排序，不虚构RICE数字。

当前基线：

- 已上线版本：`ui-20261023-policy-school-outcomes`；模型2.3，官方数据版本`20261005-defefb03`。
- 已有按分数、目标校、心仪校、已有志愿四种开始方式；三步流程、学校搜索与六项快览、收藏与对比、从收藏／对比带入心仪排序、调整前后比较、估分三情景、方案保存、解锁返回均已有实现。下一轮以整合与精简为主。
- 学校表311个历史学校／校区ID，不等于311所当年独立高中；统招记录1728条、名额分配记录28410条。
- 详细会员学校事实覆盖20校区；出口成绩63条学校档案、132条年度行，另有1条多校区合计。费用、住宿历史参考与当年可用于筛选的字段分开。
- 主表`annualFee`和`boarding`目前全部为空；不能把已有历史住宿介绍视为当年费用／住宿筛选已完整。开放日事件只涉及7校。
- 2021第三／第四批和分数段、2022第三批仍缺；7张官方表待转录。旧资料有21条待复核、283条未匹配，不能把未匹配行数当学校数。
- 案例库有3条规则案例和16条实际案例；实际案例均属第二批且完整志愿未知。完整第三／四批真实志愿样本目前为0。
- 52项测试、34项本地和34项线上浏览器检查已通过；真实家长8条任务仍未回填，微信真机及真实设备权益验收未闭环。

本轮只读代码发现的具体差距：`experience.js`学校卡片、列表筛选及详情快览仍固定取户籍生记录；`planCard()`的“继续调整”对有效结果跳至`step=analysis`；学校对比尚未展示新收录的出口／校园资料；前三志愿预览链接未携带明确方案ID；简版结果先加入通用政策说明再截取前两项，具体资格问题可能被挤出首屏。这些是下一轮需要优先复现并修正的问题，本次尚未改动。

页面呈现原则：同一时刻一个主要动作；说明先短句、细节再展开；核心资格风险始终可见。现有功能优先复用。以上为待验证的设计方案，不声称已通过真实家长测试。

## 采集与发布流程

每批资料建立一张处理台账：`任务编号 → 学校/校区ID → 字段与年份 → 来源URL/发布日期 → 原文定位 → 提取值/单位/适用范围 → 核对状态 → 展示位置/模型用途 → 发布版本`。

1. 从现有私有原文和截图提取事实，避免重复下载已取得材料；OCR只生成候选值。
2. 对应官方或校方来源，学校、校区、项目、年份必须一致。保留来源文件SHA-256、提取时间与处理版本。
3. 金额、分数、人数及比例逐项对照；矛盾资料并存并标记，不取平均后假装一致。
4. 可用于当年筛选、只可历史参考、待确认分别记录。资料页直接展示事实与适用年份，长来源说明折叠。
5. 更新前跑受影响的资格、匹配和资料呈现检查；自动抓取不得覆盖已经核对的校区别名、人工事实或适用范围。
6. 分批上线并记录新增/修改/仍缺数量。会员正文、整张资料截图和未复核OCR继续留在私有研究目录。
