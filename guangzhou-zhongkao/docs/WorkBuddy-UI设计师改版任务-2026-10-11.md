# WorkBuddy执行任务：中考助手视觉与操作流程改版

日期：2026-10-11。负责人：WorkBuddy；必须调用UI设计师专家完成设计并参与落地复核。使用对象：初三学生家长，手机和小程序优先，兼顾电脑网页。

## 用户指令与本轮目标

用户反馈：“点文字区误以为是跳转入口，按钮位置不清楚，视觉流程层面还未达标。”收款配置由用户处理，本轮聚焦现有功能的界面与操作流程。

完成标准：家长能直接分辨什么能点、点后去哪里、当前在哪一步、下一步在哪里、怎样返回修改。把现有模拟、目标校、选校排序和学校查询做成连贯的可用界面。

## 必须采用的专家协作方式

1. WorkBuddy先发现并实际调用可用的“UI设计师”专家；提供本任务书、当前页面截图、页面路由及已有用户反馈。交付中记录专家名称、调用任务、输出路径和实施后复核结论，不能只在文字中自称专家已参与。
2. UI设计师负责问题标注、信息布局、按钮与卡片规范、关键页高保真稿、手机适配和改版后视觉复核。
3. WorkBuddy负责代码落地、保留功能与数据契约、流程测试和交付。设计师输出应包含可实施尺寸、组件状态和交互说明，不能只交装饰效果图。
4. 若当前没有对应专家，明确报告不可调用的原因，并完成页面清单和问题截图；不能虚构调用记录。已具备专家时直接推进，不必逐页等待用户确认。

## A. 首先盘点全站点击区域

输出 `docs/ui-redesign-20261011/interaction-inventory.md`，每一项写清：页面、显示文字/组件、是否可点击、实际点击范围、触发后去向/动作、返回方式、改法。覆盖首页、查学校、学校详情、志愿四种入口、三步工作区、第一批资料、第二批名额分配、我的方案、我的、解锁与原生会员页。

重点检查：彩色说明卡像按钮、只有小箭头能点、标题像链接但无动作、整个学校卡点击抢占收藏/对比、步骤栏像Tab却不能回退、当前页导航未高亮、不同返回按钮行为不一致、长文字挤压按钮、多层浮动导航遮挡内容。

盘点阶段提供真实截图并标出问题，不能仅从源码推测“页面已经没问题”。

## B. 全站统一的操作规则

| 类型 | 外观与交互要求 |
| --- | --- |
| 当前主要操作 | 所在操作区域只有一个主要实心按钮；动词+结果，如“生成志愿草案”“确认志愿，查看评估”；有加载、成功、失败反馈。 |
| 次要操作 | 描边按钮，如“返回修改分数”“重新选学校”；位置固定且明显，不与主要按钮抢视觉。 |
| 普通跳转 | 明确链接样式，配“查看/进入”等动作词；不靠颜色或细小箭头单独表达可点。 |
| 首页功能入口卡 | 整张卡是同一链接，标题、说明、空白处、箭头点击均到同一正确功能。卡内不再嵌套另一可交互按钮。 |
| 学校结果卡 | 主资料区进入学校档案，收藏、对比、加入意向为独立按钮，点击互不串动作；不要用覆盖全卡的透明链接吞掉按钮。 |
| 普通说明/数据卡 | 不用按钮实心色、箭头、悬停浮起或手形光标伪装入口；结果数字仅展示，旁边单列“查看详情”。 |
| 折叠说明 | 整行标题可点击，带明确“展开/收起”和状态；纯段落不是开关。 |
| 选项与复选框 | 整个标签行可点击，有选中标记；不要只留一个很小的方框。操作选项与资料标签外观不同。 |

页面采用同一套三种字号：标题24px、正文16px、备注14px；层级优先用字重、间距、布局区分，不再出现大量零散字号。小程序按实际设备比例映射到rpx。深蓝保留品牌感，橙色集中表达操作，风险状态必须同时有文字；设计师检查文字与背景对比。

项目触控目标：主要按钮高48px，独立小按钮/图标点击区域至少44×44px，相邻操作间隔至少8px；不能靠透明点击区域重叠凑尺寸。正文行高约1.5—1.7。移动端16px侧边距，控件不横向溢出。该尺寸是本项目体验目标，不宣称是所有平台的强制标准。

## C. 页面改造安排

### UI-01：首页——先按需求进入，再查批次资料

首屏压缩装饰图和宣传语，在普通手机上看到清晰任务入口。四张整块可点的入口卡：

- 我只有大概分数 → 按分数生成志愿草案。
- 我有心仪学校 → 看看需要冲到多少分（与前一项同等明显）。
- 我选了几所学校 → 帮我安排志愿顺序。
- 我已有志愿计划 → 检查方案是否合理。

手机2×2布局，极窄屏或放大文字时转单列。存在本机草案时显示“继续上次方案”；所有入口都写明开始新草案或继续，不能悄悄清空旧方案。

搜索学校保持显眼的输入框和“查学校”按钮。下方保留按批次查询：第一批特长/自主招生，第二批名额分配，第三第四批普通志愿。自主招生不能归入第二批。批次资料与四个操作入口视觉分组，避免重复堆叠同样的大按钮。

### UI-02：志愿工作区——三步有明确进退

固定显示：1 填写条件 → 2 排列志愿 → 3 看评估。当前步骤高亮，已完成步骤可点击返回，尚不满足条件的后续步骤显示原因。

每步主操作：

| 步骤 | 左侧次操作 | 右侧主要操作 | 点击后 |
| --- | --- | --- | --- |
| 1 条件/估分 | 返回首页 | 生成志愿草案 | 校验条件，生成后打开第2步，不直接到评分 |
| 2 排列志愿 | 返回修改条件 | 确认志愿，查看评估 | 校验志愿；成功才进入第3步 |
| 3 评估 | 返回调整志愿 | 保存方案 | 保存反馈明确；导出/打印置于次级工具栏 |

手机在可用视口底部放当前步骤操作栏；为内容预留高度和安全区，避开原生tabBar、软键盘。电脑在工作区底部保持同样顺序。不要同时出现多个漂浮菜单和重复主按钮。输入错误显示在对应字段并定位第一项，草案保留。

### UI-03：心仪学校与意向排序——结果到操作有衔接

目标校：搜索选择学校 → 输入已有考生条件/选填当前分数 → “查看建议目标分”。结果明确区分历史门槛、建议目标分和与当前分数差距；接“生成配套志愿草案”，进入第2步。禁止将建议目标分描述成录取保证。

意向学校：搜索结果明确“加入意向”；已选区显示数量、学校/校区、优先想去、上移/下移、移除；手机不依赖拖拽。生成按钮标明“生成排序草案”。学校不足或无保底时解释下一步，不靠一大段提示让家长猜。

### UI-04：查学校与学校详情——容易找，也容易回来

顶部搜索常驻明显位置；筛选入口明确“筛选”，已选条件可一项移除。无结果给“清除筛选”和继续搜索。

学校卡中资料与动作分区，学校名称/主资料区进入详情；收藏、对比、加入意向显示各自状态。详情顶部显示校名和“返回学校列表”，从结果进入时返回原结果及滚动位置。学校详情的概况、录取历史、升学表现、特长自招等章节导航必须到对应位置且高亮，固定栏不得盖住标题。

### UI-05：评估页——先看结论，再看依据

先呈现“方案合理度”“可能去向”“主要风险”；不要让家长误以为方案评分就是中考分数或录取概率。每所预计去向旁有明确“查看学校”入口。

具体调整建议使用“第X批第Y志愿”的定位按钮，点击回到对应志愿行并短暂高亮。自动替换必须让用户看见改了哪所、可以撤销，并标记“已修改，需重新评估”；不能悄悄沿用旧结果。风险与置信度文案沿用通俗说明，不扩大模型结论。

### UI-06：招生资料与我的——导航一致

第一批：先选特长项目或自主招生入口，再选学校；搜索、筛选、查看简章使用明显按钮。第二批：初中选择与名额分配资格提示分层，勾选与显示同步。

小程序以现有原生tabBar为唯一底部全局导航，H5不能再叠一排。浏览器全局导航与小程序使用相同命名，已有“招生信息”入口保持可达。区分“返回上一页”和“返回首页”，后者必须真回首页但保留草案。

“我的”集中已保存方案、收藏、会员状态、使用帮助。已解锁/未解锁/服务暂不可用状态清楚；本轮只调整会员页呈现，不改价格、收款配置或授权判断。

## D. 交付顺序与范围

1. UI设计师：完成交互盘点、页面流程图和组件状态板。
2. UI设计师：交首页、填写条件、志愿表、评估、学校列表、学校详情6张手机高保真稿；另交首页和工作区电脑稿。标注按钮点击区域、跳转与返回。
3. WorkBuddy：将设计落实到现有页面，先首页及三步主流程，再学校资料与其余页面；输出可操作的本地/测试预览。
4. UI设计师复核实际截图，与稿件逐项比对；WorkBuddy完成全站回归。最后提供变更文件、截图、测试记录、预览地址及遗留问题，交Codex复验后再安排正式发布。

复用现有引擎、数据契约、路由和草稿存储。涉及事件处理可做必要调整，但不改算法评分、录取规则、招生数据或支付后端。保留既有序列号和会员兼容。本轮不添加与理解流程无关的轮播、炫目动画或无依据学校图片。配图只在解释批次/梯度/操作顺序有实际帮助时使用。

## E. 验收清单（必须有操作证据）

- [ ] 首页每张入口卡分别点击标题、说明、空白和箭头，去向一致；无文字区假入口。
- [ ] 学校卡点收藏只收藏，点对比只对比，点主资料区进详情，不触发双动作。
- [ ] 4种使用方式均能完成实际流程，生成后先到第2步，再确认评估。
- [ ] 三步返回修改不丢条件与草案；旧评估不会被误显示成新方案结果。
- [ ] 每个主要任务当前操作区只有一个主要CTA；加载/空结果/错误/禁用有明确反馈。
- [ ] 360/390/430px手机与1440px电脑无横向溢出、遮挡、按钮截字；中文放大到200%时能继续操作。
- [ ] 手指点击区域满足本任务尺寸，键盘Tab焦点可见、Enter/Space按语义有效；不以hover作为唯一点击提示。
- [ ] 手机键盘弹起时字段、提示和操作不被固定栏遮住；小程序无双底部导航。
- [ ] 从列表、评估进入学校详情再返回，回到原任务和位置；“首页”确实回首页。
- [ ] 在隔离测试环境验证未解锁、已解锁、会话失效三种UI；不用绕过生产权益进行演示。
- [ ] 至少一次真实小程序预览/真机操作记录；浏览器加zk_inmini参数不能替代真机证据。缺真机时明确待验收。

可邀请3位未参与开发的家长做简单体验：不讲解，让其找到“目标学校需要多少分”、生成并修改一份草案、查看学校后返回。记录首次点击、误点和完成情况。没有真实参与者不能编造测试结果；开发者自测单独标注。

## 参考与实现定位

点击区尺寸与间距参考W3C：https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html 。本项目选择更大的移动触控目标。按钮主次参考GOV.UK：https://design-system.service.gov.uk/components/button/ 。借鉴交互原则，不照搬政府网站视觉。

主要相关文件：index.html、dynamic-ui.js、site-shell.js、experience.css、batch-layout.css、form-layout.js、verify/index.html、app.js、intent-planner.js、experience.js、miniprogram/pages/*。应先检查生成DOM和事件绑定，避免只改静态HTML却被运行时覆盖，也避免在CSS末尾不断加!important导致全站样式冲突。
