## 必须返工的问题

### 1. P1：批次入口和招生资料卡的文字区仍点不动

复现：在首页点第一批卡的“特长与自主招生”标题；在 `/admissions/` 点“练什么，能报哪些学校？”标题。页面均未跳转。

位置：`index.html:6`、`experience.js:119`。运行时仍为 `<article>` 加内部链接。`expert-review.md` 写“批次说明卡统一为单一入口”“task-card整张卡同一入口”，与实测不符。

修正方向：单一去向的功能卡采用真正整块链接。第一批卡有特长/自招两种去向，应拆成两个清楚的整块子入口，不要给父卡套链接后继续嵌套按钮；纯说明卡去掉入口式箭头/浮起提示。逐张实点标题、说明、空白、箭头。

### 2. P1：空白方案步骤栏没有当前步骤，后续步骤未设不可用状态

复现：打开 `/verify/?new=1`。三个步骤按钮的 `active` 均为false；无 `aria-current`，结果按钮未禁用，无预先可见的不可用原因。

原因：`app.js:898` 仍按旧4步逻辑计算 `school` 为当前步骤，但 `workflow-ui.js` 已删除该步骤。新CSS中的 `[data-complete]` 和 `[data-locked]` 没有对应运行时写入。

修正方向：统一成3步状态模型，仅调整UI状态和进退，不修改录取规则。空白方案明确高亮第1步；生成后高亮第2步；确认评估后高亮第3步。已完成步骤可返回；未满足条件的步骤有语义状态和清楚原因。不能只添加CSS选择器。

### 3. P1：手机首页第4个主要入口首屏被底栏遮住

复现：390×844px。四张卡变成单列，第4张底边约857px，底栏从约783px开始，因此第4张入口说明/箭头不在首屏可见区。可以继续滚动看到，不是永久无法访问。

证据：`codex-evidence/home-mobile-viewport.png`。

修正方向：按原任务恢复常规手机2×2布局，极窄屏/放大文字时转单列；压缩首屏装饰及冗余留白，检查卡片内容不会截断。为底部导航保留安全区。

### 4. P1：电脑端出现手机底部导航

复现：1440px宽首页，上方电脑导航存在，同时底部出现61px高的4项手机导航，覆盖下方内容。

原因：`ui-redesign-20261011.css:561` 无媒体限制的 `.mobile-nav { display:flex }` 覆盖原桌面隐藏规则。

证据：`codex-evidence/home-desktop-viewport.png`。

修正方向：仅手机浏览器显示该底栏；桌面隐藏；小程序继续使用原生导航，不重复注入H5导航。

### 5. P1：带出口成绩的学校卡存在嵌套链接，浏览器生成两个主链接

复现：学校库搜索“16中本部”。同一张十六中卡片中 `.school-card-main` 实际数量为2。

原因：`experience.js:27` 的出口摘要含“查看历年与口径”的 `<a>`；`experience.js:41` 又把该摘要放进外层 `.school-card-main` 的 `<a>`。浏览器修复非法嵌套，导致主资料点击区域及键盘焦点结构不一致。此前仅以“主链接数等于卡片数”的未覆盖出口成绩检查不足。

修正方向：把出口摘要的独立章节链接放到主链接之外，或在主链接内改成非交互说明；每张卡只保留一个主资料入口，收藏/对比/章节链接在动作区。测试有出口数据和无出口数据两类学校。

### 6. P2：24/16/14字号规范没有应用到实际页面

复现：电脑首页计算样式：标题32px、正文16px、备注13px，不是任务书和设计稿的24/16/14。

原因：`experience.css` 旧全局 `!important` 和 `motion-theme.css` 继续覆盖；新样式本身也有17、18、20、28、12、13px等零散字号，不能称“只有三种字号”。

修正方向：整合既有样式来源和字号令牌，去掉冲突规则；不要靠继续添加补丁样式表堆叠。验收读取运行时computed style，不能只看设计文档。

### 7. P2：手机当前步骤操作栏未落实

复现：第2步“确认志愿，查看评估”父容器为 `position:static`，需要滚到整张长志愿表后才能操作；固定在视口底部的只有全局导航。

证据：`codex-evidence/confirm-button-mobile.png`。橙色渐变主按钮本身显示正常，不是透明按钮问题。

修正方向：按任务书设置当前步骤操作栏，只显示该步主操作和返回；与H5导航/原生tabBar分层并预留内容高度，软键盘弹起时避让。不要新增第二个同时活跃的主按钮。
