# 品沐官网下一阶段优化规划

日期：2026-10-23。状态：规划完成，尚未实施本计划中的页面改动。

2026-10-24执行更新：计划已采用，首批官网调整已上线。实际完成范围、测试、搜索平台验证及剩余事项见[执行回执](E:/pinmoo/outputs/site-human-first-work-2026-10-24/执行回执.md)。上句保留规划当日状态，不代表当前仍未实施。

本计划承接10月18日规划与10月23日收尾记录，不重置已有观察周期。目标是让真实客户更容易理解、判断和联系品沐，同时提升有价值页面的搜索发现机会、品牌事实准确性与AI引用机会。上线、收录、引用、询盘分别记录，不承诺排名或推荐比例。

## 1. 本轮判断

官网已经不缺基础内容。10月23日发布回执记录127个页面、125个站点地图URL和76篇文章；已有服务详情、顾问介绍、案例、模板、指标词典、站内搜索与分类。本轮不重建这些能力，也不为追求数量继续批量扩写。

今天实读首页、服务、案例、经营洞察、关于、联系及GEO服务页，并检查手机首页，发现主要改进空间是信息组织：

| 现状 | 对阅读的影响 | 本轮处理 |
| --- | --- | --- |
| 首页同时放置服务概览、行业问题、GEO报告说明和同名主体说明 | 客户需要在多个层次之间切换 | 主页面保留判断合作所需内容，详细解释进入对应现有内页 |
| 服务页并列四类方向、三种合作方式、七项能力 | 用户需要反复理解分类 | 服务统一为三类需求；合作方式单独说明，不再作为另一套服务分类 |
| 经营洞察默认列表很长，桌面实读约1.34万像素 | 找到适合自己的文章成本较高 | 保留搜索和分类，增加精选与可抓取分页 |
| GEO详情页多次解释问题、交付与流程 | 重要信息被重复段落稀释 | 合并商业说明，方法细节进入资料与专题文章 |
| 案例卡片标题偏长，联系页有多次相近开场 | 扫读效率仍有提升空间 | 缩短卡片概括，统一联系行动与准备资料 |

以上是页面观察与设计判断，不是已有客户测试结论。页面长度不单独作为质量评分，也不按固定字数裁切必要信息。

## 2. 信息分层

**原则：主页面帮助客户做判断，深层页面提供完整答案；两者都面向人。** 搜索访客经常直接进入服务或文章页，因此二级页面不是机器专用区。

| 层级 | 承担的工作 | 内容与入口 |
| --- | --- | --- |
| 主导航页 | 快速了解、建立信任、发起咨询 | 首页、服务、案例、经营洞察、关于、联系；短段落、明确主次，不堆关键词 |
| 服务与案例详情 | 承接明确需求，帮助判断是否适合合作 | 谁适合、解决什么、如何开展、交付什么、实际案例、边界、咨询入口 |
| 专题、文章与资料 | 详细回答搜索问题，提供可引用依据 | 原因分析、操作方法、指标口径、行业情境、资料来源、示例、工具模板 |

所有重点深层页面通过普通链接从主导航页或主题入口2–3次点击可到达。保留面包屑、关联阅读和相关服务入口。不做隐藏文字、不做只给爬虫看的版本、不创建没有入口的文章，也不批量制造只替换城市或行业名的重复页。

首页与服务页仍保留自然的标题、业务描述和必要事实，不把SEO理解为从主页面删除业务文字。现有机器可读资料只同步事实，不作为本轮主要投入方向。

Google官方明确，其AI搜索功能沿用SEO基础要求，强调可抓取内容、内链、用户体验和与可见正文一致的结构化数据，没有专门的AI优化文件要求。这不代表豆包、DeepSeek、元宝采用相同算法，后者继续用实际样本观察。[Google官方说明](https://developers.google.com/search/docs/appearance/ai-features)

## 3. 六个主页面怎么改

### 首页：一眼看懂品沐，一条顺畅的联系路径

保留现有咨询人物场景、品牌配色与轻量动效，不再次整体换皮。定位继续是“品牌电商增长顾问”，GEO是发现与获客环节之一，不把品沐重新收窄为只做GEO的公司。

建议顺序：

1. 品牌定位与一句业务说明；主行动“聊聊你的经营问题”，次行动“了解服务”。
2. 从当前问题进入三类服务，合并重复的问题卡与服务介绍。
3. 三个代表案例，每个只呈现场景、关键问题、采取的行动和详情入口。
4. 顾问简述与合作步骤，引用关于页已有真实资料，不新增未经证实的资历。
5. 三篇精选文章及一个实用资料入口，按客户决策价值选择，不只按发布时间。
6. 三个合作常见问题与联系入口。

免费GEO基础报告保留为相关需求的次级入口，不与主咨询行动争夺全站重心。首页不用同时解释报告所有章节和技术指标。

| 目前首页的详细内容 | 拟保留或迁入位置 |
| --- | --- |
| 咨询、陪跑与代运营区别；如何合作 | 首页保留短答；服务页与已有选择顾问文章给完整解释 |
| 有流量不转化 | `/services/store-diagnosis/` 与已有同主题文章 |
| 退款、投入回报、AI周报资料 | 对应退款分析、ROI复盘、经营周报服务及资料页 |
| 免费GEO报告范围与获取方式 | `/services/geo-consulting/`，联系页保留领取入口 |
| 茶叶、陈皮GEO行业问题 | 现有茶叶、陈皮服务及文章 |
| 同名企业与主体辨识 | `/about/` 的公司资料段落；页尾仍保留公司全称 |

迁移前建立内容对照表，先保证目标页已有或补齐答案，再精简首页；FAQ结构化数据随可见内容同步调整。

### 服务：统一三类需求，另列合作方式

三类服务与首页保持一致：

- 经营诊断与运营陪跑：策略、平台经营、投入复盘、数据与经营提效。
- 商品转化与复购：商品表达、SKU选择、页面、客服、直播承接、会员运营。
- 品牌搜索与GEO：品牌事实、搜索内容、AI可见度、引用与持续复测。

每类用“适合什么情况、主要交付、相关案例”说明。一次诊断、专项优化、持续陪跑是合作方式，不再混作服务分类。现有17个服务落地页先检查重叠，不急于删除或增加；例如经营诊断与店铺诊断，需要说清整体经营判断和店铺转化排查的区别。

GEO详情页合并重复模块，保留一套交付说明、一条项目流程、一份准确标注的报告示例及联系入口；复测细则、品牌事实字段与长篇解释连接到已有资料，不让客户反复读同一段营销说明。

### 案例：先看懂，再看细节

列表卡片采用“客户情境 + 关键问题”的短标题，摘要分别说明行动与实际阶段结果。案例详情继续保留问题、判断依据、动作、已发生结果和适用边界。必要事实不能为了视觉简洁被删掉。

沿用各案例对应的图片，不混用联系页或无关行业图片。示意图与AI场景保留准确身份；已确认真实的案例不重复要求用户证明，但新增客户原始报表、姓名、聊天记录或照片的公开范围需另行确认。

### 经营洞察：从文章仓库改为问题入口

保留已有搜索、分类和阅读返回体验。默认展示不超过12张文章卡，精选内容包含在其中，避免另一组重复大列表；其余用正常页码链接访问。

优先组织五组主题：选顾问与合作、商品转化、经营质量与复购、品牌搜索与GEO、茶叶与陈皮行业实践。先在现有页面组织主题入口；只有确有独立需求和足够内容时才增加独立主题URL。

分页在构建时生成可直接访问的HTML，页面之间有正常`a href`链接，各分页使用自己的canonical，不全部指回第一页。不采用仅靠“加载更多”按钮才能发现旧文章的方案，也不让任意搜索词和筛选组合生成大量待索引页面。[Google分页建议](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading)

文章采用“具体问题、原因、判断、可采取的动作”的自然叙述。适合解释的内容才使用表格与问答，不强制所有文章套统一FAQ、字数或结论模板。

### 关于：顾问信任与主体准确性

现有鲍俊文（沐风、BarryBao）介绍已经存在，本轮重点是让客户更容易看到他负责哪些判断、如何参与项目，以及哪些真实案例可以支撑这些能力。公司名称、服务地区、公开联系方式与主体辨识保留清楚，不编造奖项、合作品牌、客户评价或执业资质。

真实顾问工作照可以增强信任，但需要用户提供可公开素材；没有素材时沿用现有说明，不用生成的人物冒充真实团队。

### 联系：一个主要行动，降低准备成本

合并重复开场，核心为“带着一个经营问题来聊”。客户只需准备品牌或店铺、主要平台、当前问题三项。微信为主要行动，电话为备用；免费GEO报告作为明确的咨询目的选项，不建立另一套重复流程。

电脑展示清晰二维码，手机优先复制微信；核对操作成功、失败提示、焦点与底部安全区。资料模板作为可选准备，不新增冗长表单或阻止客户联系的必填步骤。

## 4. SEO与GEO的专业内容放在哪里

首批从现有内容选出8–12个重点页面深化，分批完成，不承诺一次改完76篇。建议服务页与资料页4–6个，相关文章4–6篇；选择依据是实际搜索问题、业务相关性、已有材料和当前内容缺口，不把下表当作已证明的搜索量排名。

| 主题 | 主要复用位置 | 应补充的具体内容 |
| --- | --- | --- |
| 如何选择电商顾问 | `/services/tmall-jd-consultant/`；已有咨询、陪跑、代运营比较文章 | 分工边界、适合阶段、首次沟通材料、可以观察的交付，不靠自称靠谱 |
| 有流量为什么没有成交 | `/services/store-diagnosis/`、`/services/page-conversion-optimization/`；商品参数与SKU文章 | 真实情境、排查顺序、示例前后差异，不虚构转化率提升 |
| 成交额之外如何看经营 | `/services/tmall-refund-rate-analysis/`、`/services/ecommerce-roi-review/`、指标词典 | 支付与净销售口径、退款时间归属、计划级投入判断、适用限制 |
| 品牌怎样被正确发现 | `/services/geo-consulting/`；品牌事实库、AI旧资料更新文章 | 品牌与公司关系、事实来源、旧信息纠错、提及与引用的区别、可复测记录 |
| 茶叶与陈皮品牌经营 | 已有茶叶、陈皮服务与案例、行业文章 | 行业购买决策、产品事实、信任材料及经营场景；避免通用文案替换行业名 |

复用已有4份运营模板、4份示例和指标词典，把解释链接到可以下载使用的资料。示例不是客户实际经营结果，保持明确标注。

重点页面可在开头给出一个简短直接的回答，随后提供情境、方法、依据与边界。保留真实作者与实际修改日期；来源优先使用原始资料和官方文档，外部观点与品沐经验分清。不新建缺少内容的英文镜像页，既有英文页面同步真实业务信息、模板与交互。

旧40题稿件继续按10月18日对照表处理：12个已有同题页面、3个同主题异稿先登记去重，21个拟补入现有文章，剩余4份原稿合并评估为“天猫与京东分别诊断”“传统品牌线下转线上”两个候选主题。上述合并尚未全部完成。本轮最多新增0–2篇有独立价值的文章，证据不足则不新增。

## 7. 验收与效果口径

**阅读与咨询：** 设计目标是30秒能说清品沐服务谁、解决什么，1分钟找到适合自己的方向，2–3次点击找到相关案例和联系入口。以真实试读记录验收，不把自动截图当用户评价。检查360、390、768、1440、1920宽度、键盘焦点、减少动态效果、关闭JavaScript后的阅读与联系入口。

**技术：** 旧文章与服务地址保持有效，内容迁移不制造孤页；必要合并另做逐页重定向清单。结构化数据和可见页面一致，FAQ不存在时不保留其声明。移动端节流Lighthouse每个关键页取3次有效运行中位数，目标性能至少90、SEO和自动无障碍至少95，同时做人工可用性检查；保留现有较好性能，不为动效增加重型视频或长期运行的3D。

**SEO：** 按页面与查询分组观察品牌词、服务决策词、经营问题词、行业问题词的展示、点击及索引状态。10月23日回执的GSC 28天窗口（9月23日–10月20日）为1点击、224展示，3个月窗口为3点击、792展示；仅作为同资源、同过滤条件的历史基线，不作为本计划收益。

**GEO：** 原144条固定问题继续保持题文与平台条件，36条新增服务商问题单独统计；分别记录正文提及、事实准确性、实际引用URL和仅显示域名的来源卡。保留会话模式、日期、版本、账号个性化影响，不将不同题组、不同平台和不同证据类型相加成推荐率。

**业务：** 现有隐私友好的事件计数只能表示页面与入口行为，不等于独立访客或真实询盘。真实询盘由用户做匿名记录，区分来源自报与系统可证实来源；以问题相关性、合作匹配与下一步推进判断质量，不凭少量样本宣称增长百分比。
